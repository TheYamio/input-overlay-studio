Стабильный релиз объединяет 0.3.3-dev.1–dev.3. Frontend и native exe пересобраны с версией 0.4.0 и собственной иконкой. Все функциональные наборы ниже повторены на финальном коде.

Всего **201 функциональная проверка**, runtime-ошибок в пройденных сценариях нет. Native-проверка дополнительно подтверждает версию в интерфейсе и декодирование новой иконки, которую отдаёт встроенный HTTP-сервер. FileVersion и ProductVersion exe — **0.4.0**. Иконка извлечена из ресурса exe и просмотрена; окно и трей используют тот же `default_window_icon`. ICO содержит размеры 16/20/24/32/40/48/64/128/256 px.

SHA-256 финального exe: `545097d42a9f6703c8e9ce82f3c8d77ad535ce463b379e774177f127abdf7173`.

В повторном native-замере: редактор + WebView2 в простое — около 390 МиБ суммарного working set и 0,006% CPU всей машины; после закрытия окна остаётся один native-процесс — 34,8 МиБ и 0,013% CPU. Новый OBS-клиент после закрытия работает. Сумма working set включает разделяемые страницы, это не уникально занятая RAM. Необработанные результаты: [native resources](performance/0.4.0/native-resources.json), [native checks](performance/0.4.0/native-results.json), [OBS checks](performance/0.4.0/obs-results.json).

Полные performance-замеры сделаны на этапе dev.3 и не повторялись после изменения номера версии и иконки: [методика и ограничения](PERFORMANCE_0.3.3.md). Нельзя обещать 60 FPS на предельной сцене из 3200 клавиш. Физический USB 8000 Hz, реальные аналоговые клавиатуры, игры/античит и длительный совместный прогон игры со стримом/записью не проверены.

Формат документа остаётся v2. Windows x64 ZIP поставляется с WebView2Loader.dll, libunwind.dll, лицензиями и документацией; WebView2 Runtime устанавливается отдельно. Исходники упаковываются из release commit, SHA-256 архивов публикуется в отдельном файле. [Порядок выпуска](RELEASING.md).

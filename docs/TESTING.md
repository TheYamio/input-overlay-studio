# Проверка

## Автоматические команды

Из `studio`: `pnpm test`, `pnpm build`, `pnpm test:browser`, `pnpm test:visual`, `pnpm test:performance`. Последняя команда запускает 60 секунд синтетического 8000 Hz ввода, использует production build и измеряет время JS-отрисовки и heap после GC. Эти значения не включают GPU raster/compositing. Для большей длительности задайте `STUDIO_STRESS_SECONDS=3600`. В UI доступен разработческий `?diagnostics=1`, где выбираются 1000/2000/4000/8000 Hz и длительность до часа.

Из корня: `cargo test --manifest-path ws-server/src-tauri/Cargo.toml --lib`. Для используемого в этой среде LLVM toolchain: `cargo +stable-x86_64-pc-windows-gnullvm ...`, с LLVM-MinGW/bin в PATH. После release build из `studio`: `node scripts/native-test.mjs`. Тест запускает именно Rust exe на 4465/4466 с изолированными данными, без остановки чужих процессов.

Артефакты — в игнорируемом `studio/artifacts`. Браузерные тесты применяют явно синтетический WS-server и проверяют renderer, reconnect, persistence и интерфейс. Native smoke проверяет настоящий HTTP/WebSocket, авторизацию, disk persistence и запуск Tauri. Он не имитирует физическое устройство. Для OBS добавлен отдельный `node scripts/obs-test.mjs`: настоящий portable OBS/CEF с production URL, alpha-каналом, сменой размера, live config update и reconnect. Отчёт: obs-results.json, изображения: obs-*.png.

## Ручная приёмка Windows 10/11 + OBS

Все следующие сценарии требуют отдельного ручного выполнения. Не считать их пройденными на основании синтетических тестов.

| Сценарий | Действие | Ожидаемый результат |
|---|---|---|
| Реальная клавиатура | WASD, Shift, Ctrl, Space, несколько удержаний; отдельно левая/правая стороны | Правильные клавиши, отпускания, отсутствие stuck keys |
| Мышь | M1–M5 одновременно, колесо вверх/вниз | Состояния независимы; wheel гаснет примерно через 110 мс |
| Analog HID | Выбрать поддерживаемый бренд/auto, медленно нажать несколько клавиш | Analog Fill соответствует нормализованной глубине, digital не пропадает |
| Relative Input | Двигать мышь в fullscreen CS2, KovaaK’s, Aim Lab и вне окна | След реагирует на raw deltas независимо от положения desktop cursor |
| Границы | Длительно вести мышь в одном направлении и возвращать | Fixed Field/Recenter не оставляют курсор навсегда на краю |
| Эффекты | Поочерёдно пять trail styles, M1/M2 ripple, key effects | Визуальные различия, активная клавиша читается при удержании |
| DPI | Одинаковое физическое движение при 800 и 1600 DPI | Нормализованный масштаб сопоставим; дистанция приблизительно одинакова |
| Distance | Сменить DPI во время работы, сбросить, включить persist, перезапустить | Старая дистанция не пересчитывается; политика запуска соблюдается |
| OBS | Copy OBS URL → Browser Source 1920×1080 | Прозрачный фон, редактор отсутствует, только реальные события |
| Без окна | Закрыть Studio, продолжить игру, открыть из трея | OBS продолжает работу; настройки сохранены |
| Reconnect | Удерживать клавишу, завершить server, вновь запустить | Состояния очищаются на отключении; после подключения удерживаемые клавиши/кнопки восстанавливаются, отпущенные остаются выключенными |
| Device removal | Отключить удерживаемую клавиатуру/мышь и подключить снова | Состояния сбрасываются по device change, список устройств обновляется |
| Privacy | FPS filter, затем disable broadcast и Apply | Лишние клавиши не передаются; capture thread останавливается на Windows |
| 1/2/4/8 kHz | На реальном соответствующем устройстве вести круги 10 минут | Нет роста памяти/отставания/заметного влияния на игру; измерить CPU/frame time |
| Частота OBS | Сравнить 30/60/120/Auto с фактическими OBS настройками | Отмечать измеренную частоту, не целевое значение настройки |
| Плохая конфигурация | Экспортировать; импортировать повреждённый/чужой JSON | Ошибка без потери текущей конфигурации |
| Восстановление | Повредить studio.json при выключенном app, запустить | Предложение backup/defaults; исходный файл сохранён при явной замене |
| Два ПК | Явный LAN host, token, HTTP и WS адреса | OBS второго ПК получает ввод; loopback остаётся default |

## Проверка математики

CS2, 800 DPI, sens 1.3, yaw .022 → **39.965… cm/360**. Изменить sens на 2.6 → 19.9825…; проверить запятую. DPI/sens/yaw ≤ 0, NaN, Infinity и неверные форматы должны отклоняться. KovaaK’s Unknown не должен становиться Source автоматически.

## Ограничения измерений

Синтетический тест проверяет обработку и bounded storage, не точность USB polling, физическую дистанцию, античит или задержку между устройством и OBS. Heap после GC за минуту — smoke check, не доказательство отсутствия всех утечек. Нужен ручной длительный прогон на целевой машине. Device enumeration может включать виртуальные HID/RDP-устройства; это список Windows Raw Input, не измерение исправности каждой физической периферии.

## Ресурсы и финальные проверки 0.3.3-dev.3

Сначала `pnpm --dir studio build`. Затем `pnpm --dir studio test:resources`: production preview на 5196, синтетический WS на 4490, отдельные сценарии простоя/ввода/общей картинки/редактора/миниатюр и повторное открытие окон. `mainThreadBusyPercent` — CDP TaskDuration / wall time: 100% означает занятый главный поток, а не весь CPU компьютера. JS heap не включает всю память браузера/GPU.

В PowerShell `$env:STUDIO_BENCH_CASE='updates'` выбирает замеры изменения одного модуля на обычной/1024/3200-key сценах; `'dense'` — активный ввод на 3200 клавишах. Без переменной выполняется основной набор. `$env:STUDIO_BENCH_LABEL='after'` выбирает имя JSON, `$env:STUDIO_BENCH_SECONDS='15'` длительность этапа. Удаляйте переменную CASE перед основным набором. Данные — `studio/artifacts/resources-*.json` и `updates-*.json`.

`$env:STUDIO_STRESS_SECONDS='180'; pnpm --dir studio test:performance` проверяет 1 440 000 синтетических mouse-moved событий в InputEngine. Heap после GC снимается раз в 30 секунд. Этот путь не измеряет настоящий USB polling или Rust Raw Input под аппаратной нагрузкой.

`$env:STUDIO_NATIVE_RESOURCES='1'` добавляет к `node scripts/native-test.mjs` замеры дерева native + WebView2 (ресурсный сценарий требует PowerShell 7 / `pwsh.exe`), стандартное событие WM_CLOSE только для собственного тестового окна, проверку продолжающего работать OBS-источника и замер после закрытия окна. `STUDIO_NATIVE_EXE` позволяет выбрать отдельный portable exe. Тестовые данные изолированы в `.tools/native-smoke`.

`$env:STUDIO_OBS_PERF_SECONDS='60'` добавляет к `node scripts/obs-test.mjs` Windows CPU/memory/GPU и OBS GetStats: native idle, общий artwork с синтетическим WS-вводом и настройки Scene 60/30 FPS. Дополнительно `$env:STUDIO_OBS_PERF_CASE='soak'` проверяет длительную работу на 30 FPS, cooldown и 3200 клавиш. OBS продолжает компоновать 60 кадров/с: Scene Animation FPS и Browser Source FPS — разные настройки. Изменение одной настройки не гарантирует уменьшения всей стоимости OBS.

`cpuMachinePercent` нормирован по всем логическим CPU; `cpuCorePercent` использует 100% на одно полностью занятое логическое ядро. Суммы Working Set и GPU DedicatedUsage по PID не являются уникальной физической памятью. Нагрузка OBS включает весь отдельный OBS с его CEF, а не только оверлей. Замеры разных приложений выполняются последовательно, без параллельной сборки.

`STUDIO_OBS_RESOURCE_ONLY=1` выбирает прогон OBS без acceptance PNG-readback. Вместе с CASE=soak выполняются 60/30 Scene FPS (по половине SECONDS), cooldown и предельные 3200 клавиш. Перед каждым запуском создаётся отдельная пустая коллекция `input-overlay-acceptance.json` без audio devices; после CreateInput проверяется ровно один Browser Source. Это исключает скрытые страницы прежних запусков с `shutdown:false`. Выбор коллекции записывается в user.ini OBS 32 и передаётся через `--collection`; старые коллекции остаются в тестовом portable-каталоге.

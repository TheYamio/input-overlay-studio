# Архитектура Input Overlay Studio

## Области ответственности

- `studio/src/main.tsx` — рабочее пространство React, холст, слои, импорт и команды. Изменения документа проходят через `SettingsService`.
- `core/architecture/` — реестр доверенных встроенных модулей, их возможностей, зависимостей и декларативных настроек.
- `settings-renderer.tsx`, `core/settings-ui/` — стандартные поля из схем и адаптеры логических операций. Сложные редакторы регистрируются как скомпилированные компоненты.
- `core/settings/` — проверка, атомарные операции, история, черновики, сохранение, разрешение конфликтов, уведомления и отдельные адаптеры Preferences/Native.
- `core/localization/` — namespaces, валидируемые языковые пакеты, английский fallback и локализация ошибок по стабильным кодам/параметрам. Пользовательский Unicode-текст не переводится.
- `renderer/scene.ts`, `renderer/modules/` — один общий планировщик, хост и независимые жизненные циклы визуальных модулей. Исторический renderer и переключатели возврата удалены.
- `ws-server/src-tauri/` — нативное приложение, Raw Input, WebSocket, HTTP с включёнными Studio/OBS и сохранение. Захват не ждёт дисковой блокировки Settings Store.

## Документ v4

Новая поддерживаемая база — **v4**. v1/v2/v3 не импортируются и не преобразуются автоматически. Номер формата, протокола, схемы модуля и версия приложения независимы. Версия приложения — 0.6.2; текущий протокол — 5.

Документ содержит `gameProfiles`, `profiles` (визуальные оверлеи), `activeProfileId`, `presets`, общие библиотеки `assets`/`shapes`, `languagePacks`, `performance` и `distance`. Идентификаторы уникальны внутри своих коллекций. Каждая композиция имеет обязательный `gameProfileId`; отсутствующие ссылки отвергаются.

Игра хранит название, игру, DPI, sensitivity, yaw, шкалу и manual cm/360. Оверлей хранит собственное название, подпись, тему, язык служебных подписей `locale` и экземпляры модулей. Игровые параметры не дублируются в оверлеях. Активная игра определяется ссылкой активного оверлея: второго независимо сохраняемого activeGameId нет.

`activeProfile` возвращает изменяемую композицию в черновике операции. `gameForProfile` разрешает ссылку. `resolvedProfile` создаёт представление для чтения/рендеринга. Результат в React-превью мемоизируется по документу, чтобы обновление локального состояния перетаскивания не возвращало старую геометрию.

## Правила профилей и наследования

- Выбор игры в списке выбирает редактор. Команда Activate game переключает live-оверлей на уже связанную композицию; при её отсутствии создаётся копия текущей с новой ссылкой.
- Дублирование оверлея копирует оформление и сохраняет ссылку на ту же игру. Изменение общего DPI действует на все связанные оверлеи.
- Дублирование игры создаёт независимую запись. Равные значения не объединяются автоматически.
- Перед удалением используемой игры явно выбирается замена. Все ссылки меняются и игра удаляется одной операцией с одним Undo.
- Последнюю игру и последний оверлей удалить нельзя. При удалении активного оверлея выбирается оставшийся для той же игры, затем первый доступный.
- Накопленная физическая дистанция не пересчитывается при изменении DPI или переключении профиля. Новые counts переводятся в сантиметры по связанной активной игре.
- Для оформления действует только явно объявленное наследование module → key/button. Global/Capture и параметры игры не становятся неявными родителями цветов или геометрии.

## Оболочка модуля

Каждый сохраняемый экземпляр содержит `id`, стабильный namespaced `type`, `schemaVersion`, `enabled`, `common`, `config` и `resources`. `common` владеет геометрией, видимостью, блокировкой, слоем, прозрачностью и именем. `config` принадлежит зарегистрированной схеме. `resources` явно перечисляет используемые растры и SVG.

Встроенные редакторы работают с типизированным плоским представлением текущего документа. Оно не является отдельной поддерживаемой версией файла. Файлы и сообщения сохраняются в канонической оболочке через `encodeDocument`; импорт использует строгую persisted-схему.

Неизвестный тип или более новая версия схемы модуля остаётся ограниченными JSON-данными. Без подходящей доверенной регистрации код не выполняется и модуль не рисуется. Общие поля можно менять без потери `config`/ресурсов. Неизвестный config ограничен по объёму, глубине, числу узлов и строкам; опасные ключи запрещены. Некорректный известный config отвергается, а не превращается в непрозрачный неизвестный.

## Сохранение, обмен и будущие версии

`SettingsService` владеет валидацией, Undo/Redo, неделимыми операциями, уведомлениями и debounce-синхронизацией. Высокочастотный ввод, held keys, анимационные timeline, временный выбор и состояние редактора не записываются в документ.

Текущий документ браузера хранится под `input-overlay-studio.document`, отдельно от UI/connection preferences. Нативная сторона сохраняет `studio.json`. Перед изменением проверяется резервная копия; ошибка записи не меняет нативную память или revision. Непрочитанные исходные данные не затираются молча.

Протокол требует явного текущего capability contract. Только Studio с поддержкой v4, module envelope, game links и visual.localization может записывать. OBS Runtime — читатель. CAS/revision, origin, sequence, ACK и защита от позднего декодирования изображения предотвращают потерю параллельных правок.

Целый документ из будущей версии открывается как защищённый оригинал: доступен экспорт исходного текста, запись поверх него блокируется. Движок будущих миграций начинает цепочку с baseline 4, работает на копиях и проверяет полный результат. Старые преобразования 1→2→3 удалены.

Экспорт конфигурации содержит весь текущий документ. Экспорт оверлея содержит одну композицию, одну связанную игру и только её ресурсы; остальные профили, пресеты и Capture-настройки исключены. Экспорт игры — отдельный декларативный пакет v1 без оформления. Пакет пресета v2 содержит оформление и ресурсы; прежний пакет v1 больше не читается. Внутренние фабричные пресеты не выдаются за внешний формат.

## Проверка контрактов

`studio/scripts/schema-contract.mjs` генерирует `studio-current.json`, `studio-model.json` и `module-configurations.json` для Rust. `--check` сверяет контракты без записи. Канонический seed и seed представления имеют отдельные имена. `modules-current.json` проверяется TypeScript и Rust, включая неизвестные модули, ресурсы и отказы. Тестовые fixtures исключены из production entry graph.

## Расширение и приёмка

Доверенный модуль регистрирует конфигурацию в ModuleConfigurationRegistry, метаданные/настройки в Catalog, UI в ModuleUIRegistry и реализацию в VisualRuntimeRegistry. Простые поля получают контролы из схемы. Внешние пакеты содержат только данные; произвольный код не загружается. Пример полного цикла без изменения центральных панелей: `studio/scripts/fixtures/architecture-acceptance.tsx`; он не включается в production.

SettingsError содержит стабильный code и неизменяемые параметры; UI использует namespace `errors`, не связывая новый контракт с английской формулировкой. Английское Error.message сохраняется для диагностики; адаптер старых/сторонних текстовых ошибок остаётся на границе UI. Идентификатор неверной настройки можно передать в params; отвергнутые значения и credentials туда не включаются.

Новый язык добавляется через пакет; Studio preferences отделены от runtime-пакетов документа. У runtime-подписей используется namespace overlay с ключами модулей. Подробности: [LOCALIZATION.md](LOCALIZATION.md). Полный набор приёмки: [TESTING.md](TESTING.md).
